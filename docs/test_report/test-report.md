## 4. 测试策略【全组统一写】

### 4.1 单元测试策略

写作指引：
说明各组是否对核心服务、类、函数进行单元测试。重点关注输入、输出、边界条件和异常路径。

建议覆盖：
- A：权限校验、用户信息校验。
- B：冲突检测、排课结果生成。
- C：选课约束检查、容量控制。
- D：帖子发布、检索逻辑。
- E：自动评分、组卷规则。
- F：绩点计算、成绩修改状态流转。

### 4.2 集成测试策略

写作指引：
说明 A-F 之间如何联调。

重点集成链路：
- A → B：教师、课程信息用于排课。
- B → C：排课结果用于选课冲突判断。
- C → F：选课结果用于成绩录入对象。
- A → D/E/F：用户身份和课程信息用于论坛、测试、成绩。
- E → F：若在线测试成绩进入成绩管理，应测试该数据流。

### 4.3 系统测试策略

写作指引：
按完整用户业务流程测试。

建议流程：
1. 管理员创建用户和课程。
2. 教务维护教室并排课。
3. 学生制定培养方案并选课。
4. 教师在论坛发公告，学生发帖回帖。
5. 教师创建题库和试卷，学生在线答题。
6. 教师录入成绩，学生查询成绩和学分进展。

### 4.4 验收测试策略

写作指引：
用需求报告中的 Validation Criteria 验收。每条核心需求都应有对应测试用例。

### 4.5 回归测试策略

写作指引：
说明每次修复缺陷后如何重新执行相关用例，特别是权限、选课、排课、成绩这类容易产生连锁影响的模块。

### 4.6 冒烟测试策略

写作指引：
每次构建后先测试最核心路径，判断版本是否可进入详细测试。

建议冒烟路径：
- 登录。
- 查看菜单权限。
- 创建课程。
- 创建排课。
- 学生选课。
- 发帖。
- 在线答题。
- 查询成绩。

- 教室时间冲突检测。
- 教室容量不足检测。
- 手动调课成功。
- 手动调课冲突提示。

重点异常：
- 无可用教室。
- 教师时间不可用。

### 5.4 C 智能选课测试用例【C 组填写】

- 正常退课。
- 选课结果查询。
- 教师导出学生名单。
- 教务控制初选/补退选时间。
- 教务手动加课。
- 在线用户连接数控制。
- 长时间停留用户强制退出。
- AI 辅助选课建议生成。

重点异常：
- 未制定培养方案直接选课。
- 课程容量已满。
- 时间冲突。
- 重复选课。
- 不在选课开放时间。
- AI 服务不可用时的提示或降级。

### 主要缺陷与问题分析

1\. **自动组卷逻辑缺陷**： 在题库题目数量少于组卷规则设定数量时（例如规则要求10道单选，题库仅有5道），系统未进行预判提示，而是生成了包含重复题目的试卷。

2\. **计时器同步问题**： 前端倒计时与后端服务器时间存在偏差，当客户端修改本地时间时，可绕过考试结束时间的限制进行答题。

3\. **自动评分精度**： 部分带有小数分值的题目在自动汇总时，总分出现浮点数精度丢失问题（如 89\.99999）。

4\. **并发稳定性**： 在模拟多用户同时点击“提交试卷”时，出现短暂的数据库死锁，导致部分学生提交失败。

### 结论

核心功能流程（组卷\-答题\-评分）已打通，但计时安全性和并发提交存在中等级别风险，建议在修复后进行一轮回归测试。
