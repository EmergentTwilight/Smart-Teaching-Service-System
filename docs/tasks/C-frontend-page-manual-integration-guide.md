# C 组前端页面手动联调操作指南

本文用于 C 组在上级集成分支上进行前端页面手动联调。目标是让联调人员按固定步骤验证学生端、教师端、教务端和 AI 降级页面，并把页面现象、操作、结果和证据完整写入 `docs/tasks/C-integration-record.md`。

## 1. 联调范围

本次页面联调覆盖：

| 页面 | 路径 | 账号角色 | 覆盖模块 |
| --- | --- | --- | --- |
| 我的培养方案 | `/selection/curriculum` | student | C1 |
| 学生选课 | `/selection/courses` | student | C1/C2/C3/C4 |
| 我的课表 | `/selection/timetable` | student | C4 |
| AI 课程推荐 | `/selection/ai` | student | C6 |
| 课程名单 | `/selection/teacher/roster` | teacher | C4 |
| 选课阶段管理 | `/selection/admin/periods` | admin/super_admin | C5 |
| 手动加课 | `/selection/admin/manual-enrollment` | admin/super_admin | C5 |

本指南只验证页面联调和前后端契约，不要求联调人员在页面上修复业务逻辑。

## 2. 联调前准备

### 2.1 固定分支和提交

1. 在终端进入项目根目录。
2. 记录当前分支和 commit：

```bash
git status --short --branch
git rev-parse --short HEAD
```

3. 在联调报告中记录：

```text
分支：
commit：
工作区是否干净：
联调日期：
联调人员：
```

如果工作区不是干净状态，先暂停页面联调，确认这些改动是否属于本次联调基线。

### 2.2 确认服务状态

1. 查看 Docker 服务：

```bash
docker compose ps
```

2. 屏幕上理论上应看到：

| 服务 | 期望状态 |
| --- | --- |
| `postgres` | Up/healthy |
| `redis` | Up/healthy |
| `server` | Up，监听 `3000` |
| `web` | Up，监听 `5173` |
| `adminer` | Up，监听 `8080` |

3. 在联调报告中记录：

```text
Docker 服务状态：通过 / 失败
异常服务：
截图或命令输出摘要：
```

### 2.3 打开前端

1. 浏览器访问：

```text
http://localhost:5173
```

2. 如果进入登录页，屏幕上应看到账号、密码输入框，以及登录按钮。
3. 如果已经登录，建议先退出当前账号，再按本指南逐个账号验证。

### 2.4 测试账号

| 账号 | 密码 | 用途 |
| --- | --- | --- |
| `student` | `student123` | 学生端页面 |
| `teacher` | `teacher123` | 教师名单页面 |
| `admin` | `Admin123` | 教务阶段管理、手动加课 |

联调报告必须记录每个账号是否能成功登录。

### 2.5 常用验证数据

以下 ID 来自 C 组 seed/verify seed。若本地数据被重置，应以当前数据库或 API smoke 结果为准。

| 用途 | 建议值 |

| C1/C2 当前学期 | `10000000-0000-4000-8000-000000000002` |
| 学生端详情验证开课 | `10000000-0000-4000-8000-000000000018` |

| 非本人教师开课 | `a1000000-0000-4000-8000-000000000011` |

如果存在 `scripts/.c4c5-verify-ids.json`，教师名单和手动加课页面优先使用该文件里的最新 ID。

结果判断口径：

| 结论 | 使用场景 |
| --- | --- |
| 通过 | 页面可访问，核心数据加载，按钮行为符合后端返回。 |
| 阻塞 | 页面白屏、登录不可用、主接口失败、角色无法进入应能进入的页面、写操作错误破坏主流程。 |
| 非阻塞 TODO | 页面可继续使用，但有待完善能力，例如 C6 AI 返回 501 降级。 |

### 4.2 我的培养方案 `/selection/curriculum`

操作步骤：

1. 在地址栏输入 `http://localhost:5173/selection/curriculum`。
2. 等待页面加载完成。

屏幕上理论上应看到：

- 页面标题：`我的培养方案`。
- 副标题：`查看您的培养方案、课程安排与学分要求。`
- 左侧或主区域卡片，标题类似 `<培养方案名称>（<专业名称>）`。
- 年度标签，例如 `年度：2026` 或当前 seed 对应年度。
- 课程分组列表，分组名可能包括：
  - `专业必修课`
  - `专业选修课`
  - `公共课`
- 每门课程显示课程代码、课程名称、学分。
- 如果有建议学期，应显示 `建议第 X 学期`。
- 右侧或下方应看到学分进展卡片和 `学分要求` 卡片。
- `学分要求` 卡片应包含：
  - `总学分要求`
  - `必修学分`

- 如果页面显示 `无法获取培养方案`，记录错误文案和接口状态码。
- 如果页面显示 `未返回培养方案数据`，记录为空数据，不要当作通过。
- 如果只看到 loading 且长时间不结束，记录为阻塞。

  - 输入框 `课程名称/代码/关键字`

#### 4.3.1 默认加载检查

操作步骤：

1. 不填写任何筛选条件。
2. 观察课程表格是否自动加载。

理论结果：

- 表格应展示课程数据，或明确显示 `暂无可选课程数据。请检查筛选条件或确认当前处于选课阶段。`
- 不应出现 `课程列表加载失败`。
- 不应出现 `当前学期不唯一`。
- Network 中 `/api/v1/course-selection/offerings/available?...` 应返回 200。

#### 4.3.2 查询和重置

操作步骤：

1. 在 `课程名称/代码/关键字` 输入框输入 `course`。
2. 点击 `查询`。
3. 观察表格刷新。
4. 在 `课程类型` 下拉框选择 `必修`。
5. 点击 `查询`。
6. 点击 `重置`。

理论结果：

- 每次点击 `查询` 后表格应刷新，页面不白屏。
- `重置` 后筛选项清空，`包含不可选课程` 保持默认勾选或恢复默认状态。
- 如果没有结果，应显示表格空状态，而不是错误弹窗。

报告记录：

```text
关键字查询是否成功：
课程类型筛选是否成功：
重置后筛选项是否清空：

```

#### 4.3.3 可选性原因

操作步骤：

1. 在课程表格中找到 `可选性` 列。
2. 找到显示 `不可选` 的课程。
3. 将鼠标悬停在 `不可选` 或旁边原因文本上。

理论结果：

- 页面应出现浮层，标题为 `不可选原因`。
- 浮层中应列出后端返回的原因，例如：
  - `课程已选`
  - `课程已满`
  - `课程有时间冲突`
  - `课程先修条件不满足`
  - `课程不在培养方案中`
- 原因应来自后端 `eligibility.reasons`，不是前端硬编码成功。

报告记录：

```text
抽查课程代码：
页面显示可选性：
悬停后是否出现“不可选原因”：
原因文本：
结论：
```

#### 4.3.5 选课按钮

注意：该步骤会写入数据。只有在确认可以污染或已准备回滚测试数据时执行。若只做只读联调，可以跳过并记录“未执行写路径”。

操作步骤：

1. 找到 `可选性` 为 `可选` 且操作列出现 `选课` 按钮的课程。
2. 点击 `选课`。
3. 屏幕应弹出确认框，标题为 `确认选课`。
4. 确认框中应显示课程名称、课程代码、学分、教师。
5. 确认框中应出现提示：选课结果取决于当前选课阶段、容量、时间冲突、先修课程和学分上限等条件。

- 学分进展和课表相关数据应刷新。
- 失败时应展示后端返回原因，不能在前端假装成功。

### 4.5 AI 课程推荐 `/selection/ai`

操作步骤：

- 页面标题：`AI 课程推荐`。
- 副标题：`仅展示解释与建议，不会写入选课记录。`

- 如果尚未生成建议，应显示：`暂无建议，可继续使用基础课程搜索与选课流程。`

操作步骤：

1. 保持 `返回数量` 为 `5`。
2. 点击 `生成建议`。

- 如果 C6 后端仍是 TODO/501，页面应显示 warning：
  - `AI 推荐失败，已降级为基础课程查询`
  - 描述包含 `AI 推荐服务暂时不可用，系统将继续保留基础课程查询与正式选课流程。`

理论结果：

- 成功时应显示课程名称、`当前可选` 或 `当前不可选` 标签、解释文本和 disclaimer。
- 失败时应显示 `AI 解释失败`，并说明可继续普通选课流程。

## 10. 最终通过标准

满足以下条件，才建议从页面联调进入合并评估：

1. `student`、`teacher`、`admin` 三类账号均能登录。
2. `/selection/curriculum` 能展示培养方案或明确错误，不白屏。
3. `/selection/courses` 默认可加载，不再出现当前学期不唯一。
4. 课程详情抽屉可打开，刷新正常。
5. 可选性原因可见，且来自后端返回。
6. `/selection/timetable` 能展示课表或明确空状态。
7. `/selection/teacher/roster` 能查询本人任课名单。
8. 非本人教师开课名单返回 403，页面不泄露名单。
9. `/selection/admin/periods` 能展示阶段列表，编辑回填正常。
10. `/selection/admin/manual-enrollment` 前端必填校验正常。
11. `/selection/ai` 在 AI 不可用时展示降级提示，不影响普通选课。
12. 未登录和错误角色访问不会泄露页面数据。
13. 前端 typecheck 通过。
14. 所有写路径都记录了数据 ID、结果和回滚口径。
15. 所有剩余问题都写入 `docs/tasks/C-integration-record.md`，并标明 P0/P1/P2/P3。
