## 4. 测试策略【全组统一写】

### 4.1 单元测试策略

写作指引：
说明各组是否对核心服务、类、函数进行单元测试。重点关注输入、输出、边界条件和异常路径。

建议覆盖：
- A：权限校验、用户信息校验。
- B：冲突检测、排课结果生成。
- C：选课约束检查、容量控制。
- D：帖子发布、检索逻辑。
- E：自动评分、组卷规则。
- F：绩点计算、成绩修改状态流转。

### 4.2 集成测试策略

写作指引：
说明 A-F 之间如何联调。

重点集成链路：
- A → B：教师、课程信息用于排课。
- B → C：排课结果用于选课冲突判断。
- C → F：选课结果用于成绩录入对象。
- A → D/E/F：用户身份和课程信息用于论坛、测试、成绩。
- E → F：若在线测试成绩进入成绩管理，应测试该数据流。

### 4.3 系统测试策略

写作指引：
按完整用户业务流程测试。

建议流程：
1. 管理员创建用户和课程。
2. 教务维护教室并排课。
3. 学生制定培养方案并选课。
4. 教师在论坛发公告，学生发帖回帖。
5. 教师创建题库和试卷，学生在线答题。
6. 教师录入成绩，学生查询成绩和学分进展。

### 4.4 验收测试策略

写作指引：
用需求报告中的 Validation Criteria 验收。每条核心需求都应有对应测试用例。

### 4.5 回归测试策略

写作指引：
说明每次修复缺陷后如何重新执行相关用例，特别是权限、选课、排课、成绩这类容易产生连锁影响的模块。

### 4.6 冒烟测试策略

写作指引：
每次构建后先测试最核心路径，判断版本是否可进入详细测试。

建议冒烟路径：
- 登录。
- 查看菜单权限。
- 创建课程。
- 创建排课。
- 学生选课。
- 发帖。
- 在线答题。
- 查询成绩。
