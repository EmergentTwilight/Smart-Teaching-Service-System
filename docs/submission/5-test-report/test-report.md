## 4. 测试策略

### 4.1 单元测试策略

对 A 子系统既有单元测试进行完整回归，重点关注：

- 认证控制器与认证服务。
- 用户控制器与用户服务。
- 专业、课程等核心服务。
- 认证与参数校验中间件。
- 权限校验和异常路径。

### 4.2 集成测试策略

本轮对 A 子系统既有集成测试进行完整执行，并在 `develop` 集成版本上验证其稳定性。重点覆盖：

- 认证注册、登录、改密、找回密码。
- 用户列表、详情、创建、状态修改、角色分配、删除。
- 部门 CRUD 与详情查询。
- 专业 CRUD 与关联校验。
- 课程列表查询与参数校验。
- 培养方案 CRUD 与详情查询。
- 角色权限管理。

### 4.3 系统测试策略

前端系统测试按“管理员完整流程 + 教师/学生多角色联调”的方式执行：

1. 管理员登录并验证会话保持。
2. 管理员依次访问用户管理、部门管理、专业管理、角色权限、课程信息、培养方案。
3. 管理员执行搜索、查看、新增弹窗、编辑弹窗、删除确认等关键交互。
4. 教师与学生分别登录，验证菜单可见性、页面可达性和权限限制表现。
5. 对 B-F 子系统执行页面级冒烟测试，确认联调后无明显白屏、路由错误和会话异常。

### 4.4 验收测试策略

本轮验收以“是否满足演示版本交付”为判断标准：

- 核心登录与权限路径必须可用。
- A 子系统核心功能必须能通过自动化回归。
- 前端主要菜单和页面跳转必须正常。
- 不允许带着未修复的核心功能缺陷直接提交。

### 4.5 回归测试策略

对于测试中发现的缺陷，先定位问题并修复，再执行对应页面与相关流程回归：

- 缺陷修复后重新进入对应页面执行同一组操作。
- 对同模块其他类似数据场景做对比验证，确认问题不是个例误判。
- 若缺陷涉及前后端字段或空值处理，重点验证新增、查看、编辑三条链路是否一致。

### 4.6 冒烟测试策略

每次构建后优先验证以下路径：

- 登录。
- 刷新后会话保持。
- 左侧菜单展开与跳转。
- A 子系统关键页面加载。
- 教师和学生角色登录。
- 在线测试、论坛、成绩管理页面可达性。
- 登出。

### 9.3 主要缺陷分析

本轮发现的主要缺陷属于前后端联调中的空值处理不一致问题：

- 后端部门更新接口允许 `description` 为字符串或不传。
- 前端编辑弹窗在部门原始数据 `description=null` 时，直接将 `null` 回填并参与提交。
- 提交后被后端校验拦截，界面表现为点击“确定”无明显响应。

该缺陷不属于权限或核心业务逻辑错误，而是典型的接口数据约定不一致问题。修复方式为前端在编辑场景下将 `null` 归一化为空值处理，修复后回归通过。
