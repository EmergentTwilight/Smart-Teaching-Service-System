## 4. 测试策略

本次测试采用三层策略：

| 层级                | 说明                                                        |
| ------------------- | ----------------------------------------------------------- |
| Service 单元测试    | mock Prisma，验证教室、排课、自动排课核心业务逻辑           |
| 路由权限测试        | 直接执行 Express 路由中间件链，验证角色鉴权，不依赖真实端口 |
| 文档化接口/页面测试 | 记录接口实测、页面点验和已修复问题，便于回归追踪            |

重点关注：

| 重点           | 原因                                      |
| -------------- | ----------------------------------------- |
| 排课冲突       | 直接影响课程安排正确性                    |
| 教室容量和类型 | 自动排课必须满足硬约束                    |
| 教师不可用时间 | 自动排课必须避开教师不可用时段            |
| 写接口鉴权     | 学生/教师不能直接修改教室、规则、排课结果 |

| 缺陷编号  | 严重级别 | 标题                                          | 状态   | 关联用例                     |
| --------- | -------- | --------------------------------------------- | ------ | ---------------------------- |

| BUG-B-002 | 中       | 教室设备字段前后端结构不一致                  | 已修复 | TC-B-CLS-002                 |
| BUG-B-003 | 中       | 排课更新接口方法/路径不一致                   | 已修复 | B-SCH-001                    |
| BUG-B-004 | 中       | 排课冲突预校验返回不稳定                      | 已修复 | TC-B-SCH-003                 |
| BUG-B-005 | 中       | 课表导出暴露未实现格式                        | 已修复 | TC-B-TTB-001                 |
| BUG-B-006 | 中       | 规则教室类型大小写不一致影响自动排课          | 已修复 | TC-B-RUL-001                 |
| BUG-B-007 | 高       | 排课写接口只有登录校验，学生/教师可调用写操作 | 已修复 | TC-B-AUTH-002, TC-B-AUTH-003 |

主要原因：

| 类型             | 说明                                   |
| ---------------- | -------------------------------------- |
| 前后端契约不一致 | 设备字段、导出格式、枚举值曾出现不一致 |
| 权限控制遗漏     | 写接口只做登录校验，未区分角色         |
| 环境初始化不稳定 | 依赖安装和 Prisma 生成顺序影响启动     |
| 页面状态处理不足 | 部分筛选、默认值、重置行为需要补强     |
