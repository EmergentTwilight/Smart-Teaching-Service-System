## 4. 测试策略【全组统一写】

### 4.1 单元测试策略

A 组对既有核心服务和控制器测试进行完整回归，重点覆盖：

- 认证服务与认证控制器。
- 用户服务与用户控制器。
- 权限和参数校验中间件。
- 专业、课程等核心服务逻辑。
- 输入校验、异常路径、权限分支。

### 4.2 集成测试策略

本轮重点验证 A 子系统在 `develop` 集成版本上的后端集成测试是否全部通过，并关注以下链路：

- 注册、登录、修改密码、找回密码。
- 用户列表、详情、创建、状态更新、角色分配、删除。
- 部门 CRUD。
- 专业 CRUD。
- 课程查询与校验。
- 培养方案 CRUD。
- 角色权限管理。

### 4.3 系统测试策略

本轮手工系统测试按以下流程执行：

1. 使用 `admin` 登录，验证会话保持、菜单展示与 A 子系统主要页面。
2. 在用户管理、部门管理、专业管理、角色权限、课程信息、培养方案中执行查看、搜索、弹窗、编辑、删除等关键交互。
3. 使用 `teacher` 和 `student` 账号登录，验证不同角色下的访问表现与页面联调情况。
4. 对 B-F 子系统执行页面级冒烟，确认无白屏、无明显路由错误和登录态异常。

### 4.4 验收测试策略

本轮重点以以下标准判断是否达到当前阶段交付要求：

- A 子系统自动化测试必须通过。
- A 子系统前端关键页面必须可正常访问与操作。
- 登录、登出、刷新保持会话必须正常。
- 测试中发现的核心缺陷必须修复并完成回归。

### 4.5 回归测试策略

每次缺陷修复后重新执行原始复现步骤，并对相邻场景进行补充验证。本轮重点对部门编辑缺陷进行了回归确认，验证修复后：

- 原有可编辑部门不受影响。
- `description` 为空的部门记录可以正常编辑提交。

### 4.6 冒烟测试策略

本轮冒烟路径包括：

- 登录。
- 刷新后保持会话。
- 管理员查看基础信息管理菜单。
- 进入用户管理、部门管理、课程信息、培养方案。
- 教师与学生登录。
- 访问论坛、在线测试、成绩管理等页面入口。
- 登出。

### 9.3 主要缺陷分析

A 组本轮发现的主要缺陷属于前后端联调中的空值处理不一致问题：

- 后端部门更新接口允许 `description` 为字符串或不传。
- 前端编辑弹窗在部门原始数据 `description=null` 时，将 `null` 直接回填到表单并参与提交。
- 提交后被后端校验拦截，界面表现为点击“确定”后无明显反馈。

该问题属于接口数据约定与边界值处理不一致，不属于权限控制失效或核心业务规则错误。修复后已完成回归验证。

D 组缺陷主要集中在前端真实接口联调和异常提示体验：

1. BUG-D-001 属于跨模块数据来源问题。论坛模块原先依赖课程活跃统计接口或帖子列表反推课程，但学生账号没有统计接口权限，且课程暂无帖子时无法得到课程列表。修复后，论坛前端接入 C 组选课接口，学生端优先读取本人已选课程。
2. BUG-D-002 属于边界条件提示不足。附件上传失败时虽然接口会拒绝请求，但前端缺少持久可见的错误反馈。修复后，上传组件对格式、大小和接口错误统一生成提示，并在页面中保留错误 Alert。
